By **Daroc Alden**  
October 6, 2025

At the time of writing, there have been 9,099 commits in the 6.18 merge window, 8,475 non-merges and 624 merges. The changes so far include core-kernel, graphics, and networking work, among others. There are no big surprises, but several items that were discussed at this year's [ LFSMM+BPF Summit](<https://lwn.net/Articles/lsfmmbpf2025/>) have now been merged. 

The most significant changes merged so far include: 

#### Architecture-specific

  * The Spectre mitigations for Arm Cortex-A720 CPUs [ now also apply](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=3ba8d4aa42bd>) to Cortex-A720AE CPUs.
  * PowerPC [ now supports](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=a2485d06cad3>) [ BPF arenas](<https://lwn.net/Articles/961941/>) and some [associated atomic instructions](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=0c1da35b0188>), as does [RISC-V](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=fb7cefabae81>). These instructions allow BPF programs to atomically load and store values in BPF arenas for, among other purposes, asynchronous communication with user space. 
  * x86 has gained a [ `microcode=`](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=632ff6170647>) command-line option to control the behavior of the microcode loader. The new option replaces `microcode.force_minrev`, although it will also cover broader microcode-loader options in the future. 
  * The kernel can [now use more than 255 CPUs](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=fa1d117162aa>) as an x86 guest on FreeBSD version 15.0 or later. 
  * The nios2 architecture [ now supports](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=76cea30ad520>) the [ `clone3()`](<https://www.man7.org/linux/man-pages/man2/clone3.2.html>) system call. 

#### Core kernel

  * Kernel namespaces (such as network namespaces) [ can now be referred to](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=3ab378cfa793>) using file handles. The use of file handles to refer to pidfds was previously supported; this change extends that support to namespaces. 
  * Zswap now uses zsmalloc directly, so the zpool compression-configuration mechanism has [been removed](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=2ccd9fecd916>). 
  * Mixed completion queue event (CQE) sizes are now [ supported](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=5832d26433f2>) in the same ring buffer. With io_uring's growing complexity, users may want to query for the presence of different capabilities; [ that is also now supported](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=c265ae75f900>). 

#### Filesystems and block I/O

  * The bcachefs filesystem [ has been removed](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=f2c61db29f27>) in its entirety.
  * [ `pwritev2()`](<https://www.man7.org/linux/man-pages/man2/pwritev.2.html>) calls [ can now pass `RWF_NOSIGNAL`](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=db2ab24a341c>) to suppress `SIGPIPE` signals when writing to disconnected pipes or sockets.
  * Procfs [ now takes](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=46582a15c174>) an option to specify the associated PID namespace.
  * Errors about a mounted filesystem exposing data from a different user namespace will soon [ be visible](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=bfa8ee11dc13>) to users with a recent version of `mount`.
  * A set of deprecated XFS options has been [ disabled](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=f69260511c69>) by default. Several obsolete mount options have also [ been removed](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=b9a176e54162>), but online fsck [ is now enabled](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=0ff51a1fd786>) by default. Online fsck is no longer considered experimental, and so should be generally usable.
  * A new set of [ lockless bitmaps](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=5ab829f1971d>) will improve the performance of the filesystems that use them.

#### Networking

  * The [work on AccECN](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=f60034689f2c>), for accurate TCP congestion notification, has been merged. 
  * UDP receive performance [ has also been improved](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=ce463e435757>), by 47%, according to Eric Dumazet's measurements. 
  * The [ direct internal buffer sharing (dibs)](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=df1526752e0c>) work that was discussed at Netdev 0x19 has been merged. 
  * The default socket receive buffer size [ has been raised to 4MB](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=a6d4f25888b83>). 

#### Security-related

  * The audit subsystem [ can now handle](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=eb59d494eebd>) multiple Linux security modules (LSMs) being enabled at the same time. This is part of [ other work](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=5816bf4273ed>) throughout the LSM subsystem to make multiple simultaneously enabled LSMs work smoothly. 
  * The kernel now supports [ signing BPF programs](<https://lwn.net/Articles/1031854/>) — although security policies that can take advantage of this are still in progress. 
  * Encrypting TCP connections with [ PSP](<https://lwn.net/Articles/980430/>) is [ now possible](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=64d2616972b7>) as well, with [ the documentation](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=a9266275fd7b>) covering the details. 

#### Virtualization

  * The [ new virtio SPI driver](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=089558a9baac>) lets SPI device access be provided to virtual machines. 

#### Internal kernel changes

  * Filesystem encryption and verification information [ has been moved out](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=56e7b3107176>) of `struct inode`, leaving the filesystems that don't implement those features with a lower memory footprint.
  * The `WQ_UNBOUND` workqueue flag [ is being retired](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=56ce6c8b11a9>) in favor of a `WQ_PERCPU` flag with the opposite meaning, since many callers were using a per-CPU workqueue when a global workqueue would have sufficed.
  * A new [ "transitional" attribute](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=f9afce4f32e9>) for kernel configuration options should make changing the names of options less fraught. Options marked as transitional will not be selectable in user interfaces such as `make menuconfig`, and won't be included in generated configuration files, but will still be understood and processed. That lets a kernel developer set up a new option name with a default setting based on the old option, and anyone running `make olddefconfig` will be seamlessly migrated. 
  * The Rust bindings now include [now support for Linux-kernel-memory-model-compliant atomic operations](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=2387fb2a9b84>), [ using maple trees](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=da939ef4c494>), [ creating DebugFS files](<https://lwn.net/ml/all/20250904-debugfs-rust-v11-0-7d12a165685a@google.com/>), and [ manipulating bitmaps](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=11eca92a2cae>). A number of other [ APIs relevant to writing drivers](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=eb3289fc474f>) have also been added. 
  * The kernel now requires [ LLVM 15.0.0](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=aa943a280e88>) or newer to build; users of Debian Bookworm and Ubuntu Jammy may need to upgrade their toolchains to continue building the kernel with Clang. 
  * The [ work on sheaves](<https://lwn.net/Articles/1016001/>), which improves the performance of the slab allocator, has [arrived](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=b9120619246d>). 
  * The TEE subsystem can now handle [ allocating and managing hardware-protected memory](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=c924c65f52c3>). 
  * The new [ `kmalloc_nolock()`](<https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=af92793e52c3>) allows for allocation with no additional locks taken, a capability that [ prompted significant discussion](<https://lwn.net/ml/all/20250718021646.73353-1-alexei.starovoitov@gmail.com/>) on the mailing list. 

6.18 is shaping up to be a promising release. While there are no earth-shaking changes, there are a lot of disparate improvements. When the merge window closes, LWN will have a second article on all the changes that were merged after this article was written.
